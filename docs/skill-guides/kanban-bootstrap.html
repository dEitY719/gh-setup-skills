kanban-bootstrap

GitHub Projects v2 칸반 보드 부트스트랩

repo 하나에 대해 GitHub Projects v2 칸반 보드를 만들고, repo 를 연결하고, Status 필드를 6컬럼 워크플로로 교체한 보드를 산출한다.

부트스트랩 전용 origin 만 대상 6컬럼 Status --dry-run 지원 라벨 단계는 위임
01

무엇을 만들어 내는가

보드

Projects v2 보드 1개

기본 제목은 repo 이름.

연결

보드에 링크된 대상 repo

보드와 저장소를 연결한다.

필드

6컬럼 Status 필드

Backlog / In progress / In review / Approved / Ready / Done.

자동화

Done 자동 아카이브 창

기본 2d.

원격 파일

PR 템플릿생략 가능

원격 .github/pull_request_template.md. --skip-pr-template 로 생략.

출력

잔여 워크플로 체크리스트

사람이 UI 에서 직접 켜야 하는 항목을 출력한다.

02

6컬럼 Status 워크플로

기존 Status 옵션을 이 6개로 교체한다. 점선 두 컬럼은 --hide-columns 를 줬을 때 1인 repo 용으로 숨김 안내가 붙는 컬럼이다.

01Backlog
02In progress
03In review
04Approved숨김 대상
05Ready숨김 대상
06Done
점선 = --hide-columns 안내 대상 (Approved / Ready) Done = 자동 아카이브 창 기본 2d
03

언제 쓰고 언제 안 쓰는가

상황이 스킬대신 쓸 것
새 repo 에 칸반 보드를 세운다예—
라벨만 맞추면 된다아니오label-bootstrap
docs/ 골격만 필요하다아니오docs-bootstrap
이미 있는 보드의 컬럼을 손본다아니오GitHub UI (이 스킬은 부트스트랩 전용)
위임

라벨 단계는 자체 구현이 아니다

label-bootstrap 의 스크립트를 그대로 호출한다. --no-bootstrap-labels 로 생략 가능.

04

호출 형식

스킬로 호출 
/gh-setup:kanban-bootstrap [--owner <login>] [--repo <name>] [options]
셸에서 직접 
bash skills/kanban-bootstrap/lib/setup.sh [--owner <login>] [--repo <name>] [options]
9개 인자
인자의미
--owner <login>사용자 또는 조직. 생략 시 gh repo view 로 현재 repo 소유자.
--repo <name>저장소 이름. 생략 시 현재 repo.
--title <board-title>보드 제목. 기본은 repo 이름.
--auto-archive-window <dur>Done 자동 아카이브 필터 접미사. 기본 2d.
--hide-columns1인 repo 용 Approved / Ready 숨김 안내를 추가한다.
--dry-run변경 없이 계획만 출력.
--skip-pr-template원격 PR 템플릿 생성/확인을 건너뛴다.
--no-bootstrap-labels5단계 라벨 동기화를 건너뛴다.
-h, --help도움말 출력 후 종료. API 호출 없음.
일치하는 인자가 없다.
05

동작 단계

스킬 디렉터리 확인

스킬 디렉터리를 찾고 START_TS 를 기록한다.

사전 조건 점검

gh, jq, 호스트, project 토큰 스코프. 빠진 게 있으면 gh auth refresh -h <host> -s project 힌트를 내고 중단한다.

대상 repo 결정

언제나 origin 이며 원격 선택을 묻지 않는다.

옵션 파싱

--hide-columns 가 없고 개인 repo 로 보이면 한 줄로 한 번만 물어본다.

라벨 부트스트랩

형제 스킬 스크립트에 위임.

--dry-run 디스패치

실패하면 실제 실행으로 넘어가지 않는다.

실제 실행

프로젝트 생성, repo 링크, Status 필드 교체, PR 템플릿 확인.

보고

UI 체크리스트와 최종 보고 출력.

06

주의사항 / 제약

대상 고정

origin 만 대상으로 한다

다른 원격으로 조용히 넘어가지 않는다.

프라이버시

개인 repo 판정은 추론하지 않는다

협업자 수로 유추하면 그 자체가 정보 노출이므로, 컬럼 숨김 여부는 반드시 사용자에게 한 번 물어본다.

출력 금지

토큰 · 협업자 목록 · 프로젝트 ID

stdout 에 찍지 않는다.

기본 비실행

스모크 테스트는 --with-smoke-test 없이는 실행하지 않는다

도움말 성격의 명령 문자열만 출력한다.

호출 규약

모든 gh 호출은 GH_HOST 를 함께 넘긴다

--repo 만으로는 어느 서버인지 지정되지 않기 때문이다.

워크플로 설정

"Pull request linked to issue" 는 비활성화가 정답

Issue 카드는 In review 컬럼을 거치지 않는다.
