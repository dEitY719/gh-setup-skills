# Architecture Decision Records (ADR)

ADR 은 규칙이 아니라 **결정의 기록**이다. 무엇을, 왜 그렇게 정했는지 남긴다.

## 언제 쓰는가

- 되돌리기 비싼 결정을 내린 순간에 쓴다: 구조, 의존성, 데이터 형식, 공개 인터페이스, 운영 정책.
- 확립된 동작을 바꾸려면 **ADR 갱신이 먼저**다. 코드가 먼저 바뀌고 기록이 뒤따르지 않는다.
- 결정이 없으면 ADR 도 없다. 작업 실적을 남기는 용도가 아니다.
- 이미 진행된 프로젝트에 나중에 도입해도 소급하지 않는다. 다음 결정부터 쓴다.

## 파일 이름과 번호

- `NNNN-<english-kebab-slug>.md`. 번호는 네 자리이고 `0001` 에서 시작한다.
- 새 번호는 **기존 최대 번호 + 1** 이다. 손으로 고르지 않는다. 병렬 작업이 합쳐질 때 번호가 겹친다.
- 파일 이름은 영어 슬러그, 본문은 한국어로 쓴다.
- 머지 후 번호가 겹쳤다면 나중에 들어온 쪽이 새 번호를 받는다.

## 골격

`NNNN-template.md` 를 복사해 쓴다.

- **제목** — 결정을 현재형 한 문장 선언문으로 쓴다. 예: "설정은 단일 YAML 파일에 둔다".
- **상태** — `Accepted — YYYY-MM-DD.` 와 결정 주체. 대체 관계도 여기에 적는다.
- **결정** — 핵심 결정. 근거 이슈(#N)와 링크를 포함한다.
- **이유** — 왜 이 결정인가.
- **기각한 안** — 검토했지만 버린 안과 거절 사유를 표로 남긴다.
- **결과** — 결과와 영향, 관련 문서와 ADR 링크.

## 대체 흐름

결정이 바뀌면 옛 ADR 본문을 고치지 않고 새 ADR 을 쓴다.

- 새 ADR 상태 절: `Accepted — YYYY-MM-DD. 0030 을 대체한다.`
- 옛 ADR 상태 절 끝에 한 줄만 추가한다: `0031 로 대체됨 — YYYY-MM-DD.` 그 밖의 내용은 그대로 둔다.

## 도구

이 폴더는 `/gh-setup:adr-bootstrap` 으로 만들었다. 모든 쓰기 동작은 `--apply` 없이 계획만 보여준다.

- `/gh-setup:adr-bootstrap new "<제목>"` — 다음 번호로 새 ADR 을 만든다.
- `/gh-setup:adr-bootstrap supersede <번호> "<새 제목>"` — 새 ADR 을 만들고 옛 ADR 에 대체 줄을 남긴다.
- `/gh-setup:adr-bootstrap --check` — 번호 중복, 이름 규칙 위반, 상태 절 누락, 깨진 대체 참조를 찾는다. 읽기만 한다.
